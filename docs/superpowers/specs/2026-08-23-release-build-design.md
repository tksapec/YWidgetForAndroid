# Release Build Design

## Goal

Create an internally distributable `release` APK while keeping the currently verified application behavior unchanged.

## Distribution model

- Distribution target: direct APK installation for internal/personal use.
- Signing: Android's standard debug signing configuration (`signingConfigs["debug"]`).
- No dedicated production keystore is introduced.
- No keystore file or password is committed to the repository.

## Build configuration

- Keep `applicationId = "com.tksapec.ywidget"`.
- Keep `versionCode = 3` and `versionName = "1.2"` for this release-preparation step.
- Add an explicit `release` build type.
- Set the `release` signing configuration to the existing debug signing configuration.
- Keep code/resource shrinking disabled (`isMinifyEnabled = false`) so the release variant stays as close as possible to the already verified debug behavior.
- Keep the embedded Yahoo! JAPAN Weather API Client ID unchanged.
- Keep debug-only Compose UI tooling in `debugImplementation`, so it is not packaged into the release variant.

## Output

The signed APK is generated by:

```powershell
.\gradlew.bat assembleRelease
```

Expected output:

```text
app\build\outputs\apk\release\app-release.apk
```

## Verification

Before treating the APK as releasable, run on the local development PC:

```powershell
.\gradlew.bat testDebugUnitTest
.\gradlew.bat lintRelease
.\gradlew.bat assembleRelease
```

Then install the release APK on the physical test device and perform a smoke test covering:

- application startup;
- widget placement and redraw;
- news update;
- weather update;
- Yahoo! rain forecast in fixed-location mode;
- Yahoo! rain forecast in current-location mode;
- no crash during manual refresh.

## Upgrade/signature note

A release APK signed with the debug key can only update an installed APK signed with the same debug key. Replacing or regenerating the debug keystore changes the signing identity and may require uninstalling the existing app before installation.

## Non-goals

This step does not add Google Play/App Bundle publishing, a production keystore, R8/ProGuard optimization, release automation, or GitHub Actions.
